# ADR 0005 — 발견 발현과 사용 모델 (장비 사용-게이트 폐기)

## 상태
Accepted (개정: 초기의 "장비 정확-일치 사용 게이트"를 폐기)

## 맥락

발견은 행동 + 환경 + 장비 + 지식의 상호작용으로 생성된다(discovery.md). 예:
`화염 지식 + 총(firearm) + 차징 반복 → 화염탄`.

초기 버전(이 ADR의 첫 결정)은 "발견 스킬을 사용하려면 현재 로드아웃이 발견 당시 장비와
정확히 같아야 한다"는 **사용-게이트**를 두었다. 이는 잘못이었다.

## 결정

발견은 **발현 종류**에 따라 다르게 쓰이며, **사용에 장비 정확-일치 게이트는 없다.**

- **무기(Weapon)** — 합성 마법 등 공격형. **새로 슬롯에 끼는 무기 아이템**이다
  (촉매에 실린 술식, "화기 + 술식 → 마력 탄환"과 같은 새 장비). 사용 = **슬롯에 장착해
  발사**(SkillResolver). *새로 끼우는 것*이므로 "발견 당시 로드아웃과 일치"는 성립하지 않는다.
- **커맨드(Command)** — 이동/제어/유틸 능동기. **부여된 버튼 콤보**로 발동(장비 무관).
- **패시브(Passive)** — 항시 효과(별도 카테고리, 후속).

`화염 + 총`은 화염탄을 **발견시킨 조건**일 뿐이다 — 이는 트리거의 컨텍스트 요소 점수
(ADR: 5요소 점수)에 이미 반영되며, **사용을 게이트하지 않는다.** 발견 조건과 사용 조건을
혼동하지 않는다.

## 경계 / 슬라이스

- "발견된 무기를 인벤토리 아이템으로 만들어 손 슬롯에 장착"하는 것은 아이템 시스템 영역이다
  (domain-model: Item/Equipment, slotType). 슬라이스에서는 발현 분류 + 스킬 실행
  (SkillResolver)까지 구현하고, 실제 아이템 생성·장착은 런타임/후속으로 둔다.
- 권위 경계는 ADR 0004와 동일: 프로덕션에선 서버가 사용을 검증한다.

## 재개정 (2026-07): 커맨드의 장비 바인딩 (부분 재도입)

초기의 "장비 정확-일치 게이트" 폐기는 옳았으나, "장비 완전 무관"은 지나쳤다. 커맨드의
발동 콤보는 두 종류의 토큰으로 이뤄진다:

- **행동 토큰(Jump / Dodge)** — 행동에 귀속. 장비 무관, 항상 가능.
- **무기 클릭(LMB / RMB)** — 무기에 귀속. 발견 당시의 무기 카테고리로만 재현된다.

따라서 **콤보에 무기 클릭이 포함된 커맨드는, 발견 당시의 장비 카테고리(그 무기 타입)가
현재 장착돼 있어야 발동한다.** 예: `화염 + 총(firearm)`으로 발견한 커맨드는 총을 들고
있어야 재현되며, 칼(melee)로는 발동하지 않는다("화염+총 스킬을 칼로 재현"은 성립하지
않는다). 클릭이 없는 순수 행동 콤보(더블 점프 등)는 장비 무관하게 항상 발동한다.

- 게이트 대상은 **커맨드만.** 무기(슬롯 장착·발사)·패시브(항시)는 그대로 장비 무관.
- 판정: `requiredTags = (콤보에 LMB/RMB 있음) ? contextTags ∩ {melee, firearm, bow, arcane} : ∅`.
  `requiredTags ⊆ 현재 장착 장비 태그`면 발동 가능(가이드도 이 기준으로 표시/잠금).
- "발견 조건 ≠ 사용 조건"의 원칙은 유지하되, **무기에 귀속된 클릭에 한해** 장비를 요구한다
  (발견을 재현하려면 그 무기가 필요하다는, 행동+장비 상호작용의 자연스러운 귀결).
- 권위 경계는 그대로: 프로덕션에선 서버가 사용을 검증한다(ADR 0004).
