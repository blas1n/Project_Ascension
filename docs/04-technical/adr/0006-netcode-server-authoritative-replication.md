# ADR 0006 — 넷코드 모델: 서버 권위 리플리케이션 (락스텝 아님)

## 상태
Accepted

## 맥락

GameSimulation을 "결정론 코어"로 키우면서 일부 주석/문구가 **서버·클라가 동일하게 계산**한다는
뉘앙스를 풍겼다(예: 투사체 탄도가 "server and client compute the same path"). 이는 **락스텝
결정론**을 함의한다.

락스텝은 MMO에 부적합하다:
- 모든 플랫폼(서버 x64, 다양한 클라)에서 부동소수 **비트-정확** 결정론을 요구한다 — 어렵고 깨지기 쉽다.
- 모든 클라가 전체 세계를 결정론적으로 재시뮬해야 해 **MMO 규모로 확장되지 않는다.**

## 결정

넷코드 목표는 **서버 권위 리플리케이션**이다 (실제 MMO/현대 FPS의 표준).

- **서버가 GameSimulation을 권위적으로 시뮬레이션**한다 — 탄도(Ballistics), 피해(CombatResolver),
  발견 트리거(TriggerEvaluator) 등 게임 사실. (ADR 0002·0004: 사실은 서버 권위.)
- 서버가 결과 상태(엔티티 위치, 체력/집중력, 이벤트)를 **관심 영역(area-of-interest) 단위로 클라에
  리플리케이션**한다.
- **클라는 리플리케이션된 상태를 렌더링**하고, 부드러움을 위해 로컬 예측/보간을 한다 — **비트-정확
  락스텝은 불필요**하다. 클라의 로컬 물리는 보정될 수 있는 화면용 예측일 뿐이다.

**GameSimulation과 리플리케이션은 대안이 아니다.** GameSimulation = 시뮬 *로직*(서버가 실행),
리플리케이션 = 그 *결과*의 전송. 리플리케이션이 없애는 것은 **클라의 결정론적 재시뮬 필요성**이지,
서버의 시뮬 로직이 아니다.

## 함의

- **고정 스텝은 유지**한다(Ballistics.FixedStep). 리플리케이션 서버도 고정 틱으로 돈다 — 이는 락스텝
  요구사항이 아니라 서버 시뮬 스텝이다.
- "서버·클라 동일 계산" 류 문구는 **"서버 권위, 클라는 리플리케이션 뷰"** 로 정정한다.
- 슬라이스: 서버 시뮬이 없으므로 클라가 GameSimulation을 로컬로 돌린다(비계, ADR 0004). MMO에서는
  서버로 옮기고 클라는 뷰가 된다 — 코드 위치만 바뀌고 로직(GameSimulation)은 그대로다.

## 경계

실제 리플리케이션 넷코드(전송, AOI, 예측/보정, 지연 보상)는 슬라이스 범위 밖이다(CLAUDE.md: MMO
네트워킹 금지, 훅만). 이 ADR은 방향 결정 + 기존 코드/문구를 그 방향에 정렬하는 것이다.
