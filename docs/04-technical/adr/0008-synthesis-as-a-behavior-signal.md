# ADR 0008 — Synthesis is a Behavior, Not an Inference

## Status

Accepted (2026-07-13)

## 문제

발견은 "행동에서 나온다". 그런데 우리가 관측하던 행동은 **횟수뿐**이었다.

`BehaviorAccumulator`가 표현할 수 있는 것은 `Dictionary<string,int>` — 무엇을 몇 번 했는가.
`TriggerEvaluator`의 "조합(combination)"은 **서로 다른 행동 종류의 개수**였고, 장비는 **소지 상태**로
컨텍스트 점수에 들어갔다. 시간 구조도, "무엇과 무엇을 엮었는가"도 어디에도 없었다.

결과적으로 Flame Bullet은 이렇게 나왔다:

> 총과 촉매를 **들고** 있다 (태그 `firearm`, `arcane`) + 총을 **많이 쐈다** (RangedAttack ×20)
> → 점수 초과 → AI가 태그를 보고 "화염 탄환"을 지어낸다.

이건 설계 의도가 아니다. Flame Bullet의 원래 발상은 **총과 화염을 거의 동시에 써서 두 개가 합성되는
그 행위 자체**가 스킬이 되는 것이다. 아트 문서의 2슬롯 설계도 같은 말을 한다 —
*"마도 촉매 + 권총 → 탄환 강화 → 속성 부여 → 술식 발동"*.

즉 시스템은 **소지(possession)를 합성(synthesis)으로 오독**하고 있었다. AI를 탓할 수도 없다:
합성 신호가 존재하지 않으니, 태그가 유일한 단서였다.

## 결정

**합성을 1급 행동 신호로 만든다.** 추론하지 말고 관측한다.

1. **관측 (결정론적, 클라이언트 규칙)**
   서로 **다른 컨텍스트의 두 손**을 **짧은 창 안에** 쓰면 (`SynthesisDeriver`, 순수 함수),
   `Synthesis:{primer}>{delivery}` 형태의 **방향성 있는** 행동을 기록한다.
   예: `Synthesis:arcane>firearm` — 촉매를 두르고, 곧바로 쐈다.

2. **순서가 곧 차별화다**
   `arcane>firearm` (화염을 두르고 → 쏨) 과 `firearm>arcane` (쏘고 → 화염) 은 **다른 행동**이며,
   따라서 **다른 발견**이어야 한다. 전자는 탄환이 불을 싣고, 후자는 박힌 탄을 터뜨린다.
   이것이 "같은 지식, 다른 플레이 → 다른 발견"을 공짜로 실현한다.

3. **채점 (서버 규칙)**
   `Synthesis:` 접두 행동은 `SynthesisWeight`(DB 구동, 기본 25)로 채점된다 — 생짜 공격 횟수(2)보다
   압도적으로 높다. **스팸으로는 나오지 않고, 엮어야 나온다.**

4. **프롬프트 (AI 경계)**
   AI에게 명시한다: **컨텍스트 태그는 "무엇을 들고 있었나"일 뿐, 절대 융합의 근거가 아니다.**
   융합 스킬은 `Synthesis:` 신호가 실제로 있을 때에만 구성한다.

## AI 경계 (ADR 0002 유지)

합성의 **발생 여부·무엇과 무엇·어떤 순서**는 전부 **결정론적으로 관측**된다. AI는 여전히 사실을
정하지 않는다 — 관측된 합성을 **무엇처럼 보이게 할지**(스킬의 개념/이름/이펙트 그래프)만 만든다.
이 ADR은 ADR 0002/0004의 경계를 바꾸지 않는다. 오히려 AI가 소지를 근거로 사실을 **추측**하던
구멍을 막는다.

## 결과

- 총을 아무리 많이 쏴도 그것만으로는 화염 탄환이 나오지 않는다. 그건 총질 스킬이 되어야 한다.
- 촉매와 총을 **엮은** 플레이어만 융합 스킬을 얻는다. 그리고 **엮은 순서**가 무엇을 얻는지 바꾼다.
- 새 무기/원소가 추가되어도 접두 규칙이라 시드가 필요 없다 — 조합은 자동으로 열린다.

## 대안

- **태그 조합에 시너지 가중치**: 여전히 소지 기반. 같은 문제.
- **합성 쌍마다 BehaviorWeight 시드**: 조합 폭발 + 새 무기마다 시드 필요. 접두 규칙이 낫다.
- **진짜 동시성(왼손을 홀드한 채 오른손 발사)만 인정**: 더 엄격하지만 촉매가 즉발이라 현재 입력
  모델과 맞지 않는다. 짧은 창(succession)이 "거의 동시에"를 정확히 표현한다. 홀드 기반 채널링은
  나중에 창을 좁히는 방식으로 얹을 수 있다.
