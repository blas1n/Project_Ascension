# ADR 0004 — 발견 트리거 권위: 서버가 시뮬레이션을 관찰한다, 클라는 사실을 주장하지 않는다

- 상태: 채택됨
- 날짜: 2026-06-26
- 맥락: 발견 트리거(ADR 0002 핵심 4의 유의성 점수 함수)는 플레이어 행동 시그니처를 먹는다. 그 시그니처를 *누가 만들어 트리거에 먹이느냐*가 문제다. 슬라이스에선 클라의 `DiscoveryReporter`가 행동 카운트를 `POST /api/discoveries/evaluate`로 보낸다. 그러나 권위 서버 MMO에서는 서버가 이미 권위 시뮬레이션을 돌려 플레이어 행동을 직접 관찰한다 — 클라가 REST로 행동을 보내는 것은 불필요할 뿐 아니라, 클라가 사실을 주장하는 것이라 치팅 구멍이고 ADR 0002("숫자·사실은 서버 권위")와 충돌한다.

## 결정

### 원칙: 트리거는 권위 시뮬레이션을 서버에서 관찰한다

발견 트리거의 입력(행동 시그니처)은 **권위 게임 시뮬레이션을 관찰**해서 얻는다. 권위 시뮬레이션은 서버에서 돈다. 따라서 프로덕션(MMO)에서 트리거는 서버 시뮬레이션 이벤트를 직접 구독하며, **클라는 행동 사실을 주장하지 않는다** — 클라는 입력만 보내고 발견 사실은 리플리케이션으로 받는다.

### 불변: 피드만 바뀐다, 로직은 그대로

트리거 평가(`TriggerEvaluator`)와 행동 누산(`BehaviorAccumulator`)은 피드 출처와 무관하게 동일하다. `GameSimulation`은 "서버·클라 동일 결정론"으로 설계됐으므로(ADR 0001; `Health`/`CombatResolver`), MMO에선 **서버에서** 실행되고 그 실행 사실(`GameplayEvents`, ADR 0003)이 누산기를 직접 먹인다. 바뀌는 것은 *누가 먹이느냐*(클라 REST → 서버 시뮬)뿐이다.

### 슬라이스 처리: REST 리포터는 비계다

슬라이스는 MMO 네트워킹이 범위 밖이라(CLAUDE.md) **권위 서버 시뮬레이션이 아직 없다** — `GameSimulation`이 클라에서 돈다. 그 공백을 메우려고 둔 것이:

- 클라 `DiscoveryReporter` + `DiscoveryApiClient` (행동 누적 → `POST /evaluate`)
- API `POST /api/discoveries/evaluate` 엔드포인트

이들은 **슬라이스 전용 비계**다. 권위 서버 시뮬레이션이 도입되면 클라 리포터는 **삭제**되고, `EvaluateAndTriggerAsync`는 REST 핸들러가 아니라 서버 시뮬 관찰자에서 호출된다. `/evaluate`는 그때 내부/툴링 진입점으로 남거나 사라진다.

## 영향

- 슬라이스의 클라→`/evaluate` 경로는 **권위적이지 않음**(클라가 카운트를 주장). 이는 의도된 슬라이스 한계이며, 권위는 서버 시뮬 도입 시 확보된다. 슬라이스에서 발견은 "재미 검증"이 목적이지 부정 방지가 목적이 아니다.
- `DiscoveryReporter`/`DiscoveryApiClient`/`/evaluate`는 코드에 **비계**임을 명시한다(주석).
- 로컬 카탈로그(`DiscoveryEngine` + `DiscoveryCatalog`)도 ADR 0002대로 비계다 — 같은 운명(서버 트리거 함수로 수렴).
- 이 결정은 ADR 0003의 연장이다: 관찰은 실행 사실에서(0003), 그 사실의 권위 출처는 서버 시뮬레이션(0004).
